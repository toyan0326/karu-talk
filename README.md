# KaruTalk — 画面共有で「どこどこが〜」を言えるようにするドリル

**→ https://toyan0326.github.io/karu-talk/**（iPhoneで開いて、共有 →「ホーム画面に追加」）

言いたいことは決まっているのに、英語がとっさに出てこない。特に**画面共有しながら図面を説明する場面**で、
指させないぶん全部を言葉で特定しないといけなくて固まる。それだけを直すための個人用アプリ。

## 何をするアプリか

自由会話でも、お題を出されて話すものでもない。話題を考える負荷を全部こちらが持って、
**意図 → 英語の変換速度**だけを鍛える。

### 学習の単位は《型》

単語カードでもフレーズ集でもなく**型**を数える。**3日連続で言えたら卒業**して消える。
新しい型は1日4個ずつしか下りてこない（初日に30個を浴びせない）。
卒業した型も10日後・40日後に一度だけ戻ってくる。

ホームの主役は**「今日やる型」**。やれば必ず0になるので毎セッション動く。
初期実装は「未習得の型」だけを出していたが、14日ぶんを早送りして測ったら
**最初の3日間ずっと30のまま動かず、6日目にデッキが空になる**という最悪の形だった。
30日ぶんの再検証で、いまは 3日目に初回の卒業、23日目まで毎日やることがある形になっている
（それ以降は自分で入れた型が支える設計）。

型は3通りの出し方で回る。

| 出し方 | 内容 |
|---|---|
| **図（話す）** | 自動生成した伏図・断面配筋図・グラフ／表を見て、赤い部材の位置を英語で説明する |
| **意図（話す）** | 日本語の意図が出る。それを英語で言う（画面共有の決まり文句、自分の失敗から作った型） |
| **図（聞く）** | 設定でONにすると入る。同じ図に番号を4つ振り、1つを読み上げるので、聞き取ってタップする |

位置関係の型を自分で登録すると混ざるので、同じ文の丸暗記にならない。

### リスニング（オプション）

話すドリルのちょうど裏返し。**相手が言った場所を聞き取って図の上で当てる**——画面共有の会議で
実際にやっている動作そのもの。設定の「リスニングを混ぜる」をONにすると、1セッションの頭に2〜3問入る。

図の正解はこちらが持っているので、**タップした瞬間に判定が決まる**。APIも通信も要らないので速く、
無料で、オフラインでも動く。読み上げ速度は 0.85x〜1.3x で変えられる（会議は1.3xくらいの体感）。

選択肢は「同じ物の別の呼び方」が並ばないようにしてある。たとえば「上端筋の列」と「その列の左の隅筋」は
どちらも正解になってしまうので、要素ごとに `set`（同じ物理要素かどうか）を持たせて同居を禁じている。
480試行で set の重複・ラベルの重複・マーカーの重なり いずれも0件を確認済み。

聞く側の成績は型ごとに別勘定（`listenStreak`）で、**卒業の条件は話す側のまま**。
検証済みのスケジュールを壊さないため。

### 「今日これ言えなかった」を貯めて、翌日の問題にする

ホームに常設のボタンから、**音声（日本語でいい）／テキスト／スクショ**で放り込む。
会議直後に10秒で入れられないと貯まらないので、整形はしない。受信箱に溜めるだけ。

あとで「型にする」を押すと、1件が次のように化ける。

```
「開口の真下の梁だ、って言えなかった」
   ↓
型      : X is directly below Y  （AがBの真下にある）
注意点  : under は覆う含み。離れた上下は below
変奏3問 : 配管がスラブの真下を通っている / 検査口が階段の真下にある / この柱が上階の真下に来ていない
   ＋ relation=below なので、断面図を見て答える問題も混ざる
```

**1件の失敗が、型1つ＋実際に使う問題4〜5問になる。** これが単なるメモ帳との違い。

### 判定と解説

「一字一句合っているか」ではなく**伝わったかどうか**で判定する。そのうえで3層で返す。

1. **通じたか** — 場所が特定できたか
2. **最小の手直し** — 言った文の骨格をそのまま残し、誤りだけをその場で直す
3. **もう一段スムーズに** — 書き換えた自然な言い方はここにだけ置く

2が一番大事なところ。全部書き換えた模範解答は自分の言い方を殺すので出さない。
プロンプトは「彼が言った節は消すな。冗長は誤りではない。ただし文法の誤りはその場で直せ」まで
締めてある（緩めるとモデルは勝手に短く書き直す。実際にそうなった）。

## 技術構成

ビルド不要の静的サイト。サーバー側の処理は無い。

```
index.html    画面とスタイル
app.js        ドリル進行・計測・判定・受信箱・間隔反復
figures.js    伏図/断面配筋/グラフ表の自動生成。素の図＋要素一覧を返し、
              genFigure()=話す用（1つ赤くする） / genListening()=聞く用（4つに番号）に分岐
patterns.js   組み込みの型30個（位置関係8 + 画面共有の決まり文句 + 配筋の言い回し）
```

- **自動生成図では画像をAPIに送らない。** 生成した側が正解（「2通り、Z-W間の大梁」）を持っているので、
  テキストで照合するほうが確実で速くて安い。画像を送るのは**ユーザー自身のスクショのときだけ**。
  `genFigure(relation)` は指定した位置関係を使わないと答えられない図を返す。
  480試行で relation の取り違え0件を確認済み（緩い実装では取り違えが出た）。
- **出だし秒(TTFW)の計測**: Web Audio の ScriptProcessorNode（オーディオスレッド駆動）でRMSを監視し、
  最初の400msでノイズフロアを測ってから、しきい値超えが3フレーム(≒64ms)続いた瞬間を「話し始めた」と判定。
  音声認識にもネットにも依存しない。requestAnimationFrame だと**タブが裏に回った瞬間に検出だけ止まり、
  カウンタは進んで計測が壊れる**（実際に踏んだ）。ただし iOS はバックグラウンドで AudioContext ごと
  止まるので、前面にある間の話。
  検証: 2.000秒ちょうどに音声を流し込んで **実測2.09秒**。
- **判定**: MediaRecorder の音声（＋必要ならスクショ）を Gemini に1回投げるだけ。`responseSchema` でJSON固定。
  録音は24kbps。実測した組み合わせ:

  | 送るもの | 結果 |
  |---|---|
  | Chrome の MediaRecorder が吐いた webm/opus | 書き起こし一致・4.6秒 |
  | fragmented MP4 + AAC（**iOS Safari が吐く形式**） | 書き起こし一致・3.0秒 |
  | 図(PNG) + 音声 を同時 | 位置判定まで通る・4.6秒 |
  | 日本語の音声メモ（受信箱→型の抽出） | relation/変奏3件とも妥当・3.3秒 |

- **時刻の源は `Date.now()` 1本**。`new Date()` を直に呼ぶと日付判定だけ早送りが効かず、
  スケジュール検証の結果を読み違える（実際に読み違えた）。
- 記録は `localStorage`（`karutalk.v2`）。**スクショだけ IndexedDB**（localStorageだとすぐ溢れる）。
  外に出るのは録音した音声・スクショ・APIキーだけで、送り先はGoogleのGemini APIのみ。

### 声

読み上げは端末の標準TTS。設定で**声とピッチを選べる**（ピッチを上げるほど若く聞こえる。既定1.15）。
macOSには効果音のような声が大量に入っていて、名前はOSの言語で localize される（`オルガン` `道化` など）ので、
英語名・日本語名の両方で除外している。自然に聞こえるものは「おすすめ」に分けて上に出す。

**iPhoneは 設定→アクセシビリティ→読み上げコンテンツ→声→英語 から高音質の声を追加できる**
（Ava / Zoe / Nicky など）。標準の声より格段に自然で、これが一番効く。

より根本的には [HeadTTS](https://github.com/met4citizen/HeadTTS)（MIT、Kokoro神経TTS）が
ブラウザ内で動き、**音素レベルのタイムスタンプとビゼームIDまで出せる**。
声質も口の同期精度も上がるが、初回のモデル読み込みが重くWebGPU前提なので未導入。

## 使い方

1. 設定で **Gemini APIキー** を入れる（[Google AI Studio](https://aistudio.google.com/apikey)）。端末のlocalStorageにだけ保存される。
2. 「ドリルをやる」。1セッション8問。
3. 会議で言えなかったことは、その場で **🎤 今日これ言えなかった** に放り込む。
4. iPhoneでは Safari の共有 →「ホーム画面に追加」。

**キーも学習記録も、その端末のブラウザから外に出ません。** リポジトリは公開だが中身はコードだけ。

**マイクを使うには HTTPS が必須**（`localhost` は例外）。`http://192.168.x.x` では Safari が
`navigator.mediaDevices` すら渡さないので、ホーム画面でその旨を出して開始ボタンを止めている。

### ローカルで動かす

`KaruTalkを起動.command` をダブルクリック。または:

```bash
cd ~/dev/karu-talk && python3 -m http.server 8772
```

### 更新のしかた

```bash
cd ~/dev/karu-talk && git push          # GitHub Pages が数十秒で反映する
```

**`index.html` の `?v=N` を必ず上げること。** Safariは強くキャッシュするので、上げないと古いコードのまま動く。
ただし `index.html` 自体にはバージョンが無いので、indexがキャッシュされていると `?v=N` の更新自体が届かない。
反映されないときはSafariで開き直す（ホーム画面のアイコンから開いた場合は特に）。

### NASにも置く場合（任意）

家のLAN内の控え。ただし `http://192.168.1.22/karu-talk/` は**HTTPSでないのでマイクが使えない**。

```bash
cp index.html app.js figures.js patterns.js manifest.json icon-*.png /Volumes/web/karu-talk/
```

NAS配信でマイクまで使うには、ルーターでの 80/443 転送＋Synology DDNS＋Let's Encrypt が要る。
**GW040-NS(VNPT) はログイン不明・UPnPも無効**だったため、この道は断念して GitHub Pages にした。

## アバター

出題者の顔（`emi.jpg`／english-ai-chat から持ってきた**生成された架空の人物**）が、
ホーム・聞き取り問題・結果画面に出て、読み上げに合わせて口が動く。設定でOFFにできる。

- **口**: 唇の合わせ目のカーブに沿って開閉させる。彼女は笑った口なので、楕円で開けると
  形がずれて「貼り付けた口」に見えた。実測したカーブ（左右の口角＋中央）に沿わせている。
- **同期**: TTSは音素の時刻をくれないので、テキストを音節っぽく割り母音から口を決め、
  発話の推定尺（英語はおよそ毎秒14文字）いっぱいに引き伸ばす。完全同期ではないが、
  「口が動かない」「音が終わったのに動き続ける」という不自然さは消える。
- **目・口とも生成パッチで動く**（`face/`、17枚）。目は開→半分→ほぼ→完全の4段階、
  口は AA/E/I/O/U/FV/MBP/L/S の9形（うち6形は半開きの中割りつき）。
  形そのものは写真なので混ぜられないが、**開き具合は補間する**ので半開きのコマを通って開閉する。
- **位置合わせは「口の形が変わっても動かない領域」だけで測る。** いま使っているのは
  額・目・眉・鼻（y 92〜200）。ここに至るまでに2回失敗している:
  1. 顎まで比較に入れた → 口が開いて顎が下がったぶんに引っ張られ**口全体が下にずれた**
  2. その反省で「鼻の下〜人中」の細い帯だけで詰めた → **U(唇をすぼめる)/L(舌)/S は
     人中そのものが変形する**ため合わせが流れ、口元が前に突き出た顔になった
     （縦のずれが他より14px大きくなっていた）
- 切り抜きは矩形ではなく**楕円**。矩形だと顎や頬の角を持ち込んで暗い四角が出る（実際に出た）。
- **確認は必ず原寸で。** 縮小した一覧では上の破綻を見落とした。
- **首の動き**: 比が無理数に近いサイン波を3本重ねて周期を感じさせないようにし、
  回転軸を**首の付け根**に置く（頭の中心で回すと首から上だけ振れて不自然）。
  回転で四隅が欠けないよう1.02倍で描く。
- パッチが無い場合は、まぶたの輪郭カーブでクリップするワープに自動で戻る。

### 中割りフレームを入れる（まばたきと口の精度を上げる）

```bash
python3 tools/make-face-frames.py        # face/ に生成、frames.json も書く
python3 tools/make-face-frames.py --dry-run
```

目の開閉4段階と口の形8種×3段階を画像モデルで生成し、**目・口の領域だけを切り出して
縁をぼかしたパッチ**にする。パッチは元画像とピクセルが揃うので、貼ってもズレない
（生成画像をそのまま連番再生すると、顔の位置がわずかに動いてジッターになる）。

`avatar.js` は `face/frames.json` があれば自動でパッチ方式に切り替わり、無ければ口のワープに戻る。

**注意: このAPIキーの無料枠には画像生成の割当が無い（実測で確定）。**

- 全54モデルをページングして確認 → 画像モデルは7つ、**Imagen系は存在しない**
- `responseModalities` 3通り × エンドポイント `v1`/`v1beta` を試して全部同じ 429
- 太平洋時間の日付が変わった後、**3時間にわたり37回**叩き続けたが全部 429
  （`GenerateRequestsPerDayPerProjectPerModel-FreeTier`）。同じ鍵でテキストモデルは通る

つまり「使い切った」のではなく**無料枠に画像生成の枠が無い**。待っても復活しない。
使うには**課金を有効にする**（9枚なら数十円）か、別の手段で作った画像を
`tools/FRAMES-REQUEST.md` の手順で持ち込む。
